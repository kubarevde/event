# Лендинг мероприятия с админкой

Next.js 15 + Tailwind. Тексты, картинки, форма заявки и статистика управляются из админки — код трогать не нужно.

## Что есть в админке (`/admin`)

| Раздел | Что делает |
|---|---|
| **Статистика** | Посетители, визиты, просмотры, заявки и конверсия за период; графики по дням; воронка (визит → клик «Подать заявку» → дошли до формы → начали заполнять → отправили); источники переходов, UTM-метки, устройства, браузеры, активность по часам. Кнопка «Отчёт CSV». |
| **Заявки** | Таблица заявок с фильтрами по форме, статусу и периоду, статусы (новая / в работе / подтверждена / оплачена / отклонена), комментарий менеджера, выгрузка в CSV (открывается в Excel). |
| **Формы** | Конструктор форм: поля «строка», «текст», email, телефон, число, выпадающий список, радио, несколько вариантов, галочка, согласие на обработку ПДн. Обязательность, порядок, ширина, подсказки, живой предпросмотр. |
| **Контент сайта** | Все тексты всех блоков, дата и место, цена, логотип и фирменные цвета, спикеры с фото, FAQ, меню, подвал, SEO. Любой блок можно скрыть. |

Статистика собирается самим сайтом (без Яндекс.Метрики и внешних счётчиков): боты и залогиненный администратор не учитываются.
Защита формы от спама: скрытое поле-ловушка, проверка скорости заполнения и лимит заявок с одного IP.

## Установка на сервер (Docker)

Нужен сервер с Docker (Ubuntu/Debian: `curl -fsSL https://get.docker.com | sh`).
Сайт работает за WAF: WAF принимает HTTPS и выдаёт сертификат, а на сервер проксирует запросы
по http на порт `APP_PORT` (по умолчанию 80). В WAF укажите IP сервера и этот порт.

### Вариант 1 — с GitHub (рекомендуется)

```bash
git clone https://github.com/kubarevde/event.git && cd event
cp .env.example .env
nano .env                      # ADMIN_PASSWORD, SESSION_SECRET, при необходимости APP_PORT
docker compose up -d --build
```

Сайт откроется на `https://ваш-домен` (через WAF), админка — на `https://ваш-домен/admin`.

Обновление после изменений в репозитории:

```bash
cd event && git pull && docker compose up -d --build
```

### Вариант 2 — готовый архив (сервер без доступа к GitHub)

На любой машине с Docker и этим репозиторием:

```bash
./deploy/make-bundle.sh        # создаст event-bundle.tar.gz (сервер на ARM: PLATFORM=linux/arm64)
```

Скопируйте архив на сервер и там:

```bash
tar -xzf event-bundle.tar.gz && cd event
docker load -i images.tar
cp .env.example .env && nano .env
docker compose up -d --no-build
```

### Настройки для WAF

- **Закройте порт от всех, кроме WAF**, иначе сайт можно открыть напрямую по IP в обход защиты.
  Например, через ufw: `ufw allow from <IP-адреса WAF> to any port 80` (диапазоны IP даёт провайдер WAF).
  Учтите, что Docker публикует порты в обход ufw, поэтому надёжнее ограничить доступ в фаерволе хостинга.
- **Реальный IP посетителя.** Он нужен для лимитов на заявки и вход в админку. По умолчанию берётся
  последний адрес из `X-Forwarded-For`. Если WAF передаёт IP в отдельном заголовке
  (например `X-Real-IP`), укажите его в `.env`: `CLIENT_IP_HEADER=X-Real-IP`.
- `INSECURE_COOKIES` оставьте пустым: посетители заходят по https через WAF.

### Данные и бэкапы

База (контент, заявки, статистика) и загруженные картинки лежат в Docker-томе `site-data`.
Он переживает перезапуски и обновления. **Не запускайте `docker compose down -v`**: флаг `-v` удалит данные.

```bash
./deploy/backup.sh                              # → backups/site-ДАТА.tar.gz, сайт не останавливается
./deploy/restore.sh backups/site-ДАТА.tar.gz    # восстановление
```

Ежедневный бэкап через cron (`crontab -e`):

```
0 3 * * * cd /root/event && ./deploy/backup.sh >/dev/null 2>&1
```

### Полезные команды

```bash
docker compose ps              # состояние контейнеров
docker compose logs -f app     # логи сайта
docker compose restart app     # перезапуск после правки .env
```

Чтобы проверить сайт напрямую по `http://IP-сервера` без WAF, временно задайте `INSECURE_COOKIES=1`,
иначе браузер не сохранит вход в админку.

## Локальная разработка

```bash
cp .env.example .env.local     # достаточно ADMIN_PASSWORD
npm install
npm run dev                    # http://localhost:3000, админка — /admin
```

Данные при этом хранятся в папке `storage/`.

## Как сделать новый сайт на этой основе

1. Скопируйте репозиторий, задайте `ADMIN_PASSWORD`, запустите.
2. В админке «Контент сайта» замените тексты, логотип, цвета, дату и место.
3. В «Формы» настройте поля заявки.

## Структура

- `app/page.tsx` — лендинг, читает контент из базы
- `app/admin/*` — админка; `middleware.ts` закрывает её паролем
- `app/api/*` — приём заявок, трекинг, API админки
- `lib/content.ts` — модель контента и значения по умолчанию
- `lib/content-schema.ts` — какие поля показывает редактор контента
- `lib/forms.ts` — модель формы и проверка ответов
- `lib/analytics.ts` — сбор и отчёты статистики
